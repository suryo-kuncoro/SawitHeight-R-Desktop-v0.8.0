# SawitHeight R v0.7.0 — Split Period Processing

## Tujuan perubahan
Metodologi ilmiah tetap mengikuti tutorial v0.6.0 (relative P95, terrain QC, presence support, T_TECH, peer residual), tetapi eksekusi aplikasi dipisah menjadi dua proses.

### A. Process One Period
Satu LAS/LAZ diproses mandiri menjadi `period_manifest.json`, `metrics_<PERIOD>.csv`, `metrics_<PERIOD>.shp`, terrain QC, normalized LAZ dan nCHM opsional.

Registrasi GCP/PPK tidak dipaksakan di aplikasi. Input dianggap sudah berada pada reference frame XY yang benar dan pengguna wajib mengonfirmasi alignment terhadap TREE_ID.

### B. Compare 2 Periods
Aplikasi membaca dua folder Period Package. LAS tidak dibuka ulang. Delta multi-metrik, T_TERRAIN, T_METRIC, T_TECH, peer-based lower residual, serta zone re-check dihitung dari hasil periode yang sudah tervalidasi.

Output operasional disederhanakan menjadi dua rekomendasi:
- `RECHECK`
- `NO_RECHECK`

Field status detail tetap disimpan untuk audit penyebab.

## Live log
Kedua proses memakai structured R log + stdout/stderr + heartbeat Electron. Proses berat tetap menampilkan elapsed time dan idle time sehingga pengguna dapat membedakan proses aktif dari hang.
